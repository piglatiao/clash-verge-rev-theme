# 主题设计指南：命名、取色与常见坑

## 一、命名规范

主题名统一为 **四字中文 + 英文驼峰**，例如 `夏日晴空 SummerGlass`、`卡通大海 OceanToon`。

| 项目 | 规则 | 示例 |
|---|---|---|
| 中文名 | 四字，描述画面主体/氛围，不用「主题」「壁纸」这类空词 | 白墙学园、灯宵夏祭、纱帘红裙 |
| 英文名 | 两个英文单词驼峰拼接，非直译，取意境 | WhiteCampus、LanternFest、ScarletVeil |
| 目录 slug | 英文名转小写连字符 | `white-campus`、`lantern-fest` |
| 源图文件名 | `中文名-英文名.jpg` | `白墙学园-WhiteCampus.jpg` |
| CSS 文件 | `clash-verge-<slug>-<tier>.css` | `clash-verge-white-campus-normal.css` |

命名要能反推画面：看到「灯宵夏祭」就该想到灯笼与夜色。同一批主题之间不要撞意境
（避免出现两个「静谧」「时光」这类可互换的名字）。

## 二、取色规则

三个关键色，全部从图里取，不拍脑袋：

| 色 | 取法 | 用途 |
|---|---|---|
| **primary** 主色 | 画面里**最稳的那个色块**：人像取服装/主体色，插画取主体或关键道具色，风景取天空/植被主色。明度建议 0.25–0.60 | 按钮、选中态、链接、进度条 |
| **light** 亮部 | 主色同色相提亮约 15–20%，脚本缺省自动推导 | 渐变端点、焦点描边、Tabs 指示条 |
| **text** 正文 | 画面**最深暗部**的近黑版，保留一点主色色相 | 正文、标题、表单文字 |

配一条规则：**主色要与壁纸同源**。卡片玻璃层是半透明白雾，透出的壁纸会和主色同屏出现，
如果主色是凭空挑的（比如给粉色壁纸配蓝主色），会立刻显脏。

判断是否同源的土办法：把主色和壁纸主色板放在一起，色相差 < 60° 或者两者是明确互补
（如蓝紫背景 + 暖橘灯）都算成立；色相差 90°–150° 的中不溜最容易翻车。

### 用 analyze_image.py 辅助

```bash
python scripts/analyze_image.py 壁纸.jpg
```

输出主色板（含占比/明度/饱和度）、按「面积 × 饱和度」排序的主色候选、以及风险提示
（过暗 / 过亮 / 低对比 / 宽高比异常）。候选只是起点，**最终仍要对着图判断**
——占比最大的色往往是背景墙/天空，未必适合当主色。

## 三、常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 卡片看不见轮廓 | 壁纸太亮，白雾 α .08 在近白背景上不可见 | 主色压深（明度 ≤0.45）；或让用户选 normal 档 |
| 文字读不清 | 壁纸明暗反差大，深色文字压在暗区上 | 靠 `text-shadow: 0 1px 2px rgba(255,255,255,.65)` 兜底；极端情况调卡片 α |
| 整块背景糊成斑 | 多个嵌套元素加了 `backdrop-filter` | ultra 档零模糊；不给 `.MuiList-root` 加滤镜（见 css-classnames.md 第四节） |
| 每个列表行都有壁纸 | 壁纸挂到了后代元素 | 壁纸只挂 `html, body, #root` |
| CSS 太大粘不进输入框 | 高细节插画 JPEG 压不动 | 脚本会自动降分辨率保质量；仍大就在 spec 里调 `--wall-budget` |
| 换客户端版本后样式丢了 | 用了 `css-xxxxxx` 哈希类 | 只用稳定类名（见 css-classnames.md） |

## 四、spec.json 字段表

最小可用（只给 src + primary，其余自动推导）：

```json
{
  "out": "themes",
  "themes": [
    {"src": "壁纸/我的猫.jpg", "zh": "午后橘猫", "en": "CatNap",
     "slug": "cat-nap", "primary": "#C08040"}
  ]
}
```

完整字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `src` | ✅ | 壁纸路径（相对或绝对） |
| `primary` | ✅ | 主色 `#RRGGBB` |
| `zh` / `en` | 建议 | 中文名 / 英文名；缺省回落到 slug |
| `slug` | 建议 | 目录名；缺省由 en 小写连字符化 |
| `emoji` |  | 根 README 小节图标，缺省 🎨 |
| `new_name` |  | 非空则把源图重命名为 `new_name.jpg`（不含扩展名） |
| `light` |  | 亮部；缺省自动推导 |
| `text` |  | 正文色；缺省自动推导 |
| `shadow` |  | 阴影 RGB 三元组；缺省自动推导 |
| `desc` |  | 一句话描述，进 README 导语与根 README |
| `note` |  | 设计说明，进 README「设计说明」段 |
| `palette` |  | 三元组数组 `[用途, 色值, 来源]`，缺省自动生成三条 |
| `ui` |  | 预览界面文案覆盖，如 `{"nav1":"首页","page_title":"订阅"}` |

## 五、产物结构

```
themes/<slug>/
├── README.md                        档位表 / 配色表 / 预览 / 安装 / 换壁纸
├── clash-verge-<slug>-ultra.css     纯透明
├── clash-verge-<slug>-high.css      blur 10px
├── clash-verge-<slug>-normal.css    blur 18px
└── previews/{ultra,high,normal}.jpg 1200x700（JPEG q95 4:4:4）
```

预览图是用 DOM mock 渲染的（复刻真实嵌套层级），**不是真客户端截图**。
格式默认 JPEG q95：真彩 PNG 单张可达 1.5MB，q95 JPEG 只有 1/3 体积且肉眼无损。
**不要用 256 色调色板量化来省体积**——渐变与磨砂层会立刻出现抖动噪点和色带。
它的价值在于：mock 用同一套类名，所以能通过 computed style 反证选择器是否命中；
排版细节仍可能与客户端有出入，交给用户实际粘贴后确认。
